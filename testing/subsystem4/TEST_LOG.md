### S4-U16 bench procedure: IMU lost while armed

1. Robot on a stand (wheels free), USB console logging to a file, MQTT dashboard connected. Flash the `integrated` build with the S4-U15 change.
2. Start a run (arm) with the line sensors over a black line so `[MOTION] state=2` appears and the wheels turn.
3. Pull the IMU SDA jumper (LSM303DLHC breakout) and start a stopwatch or phone slow-motion video of the wheels.
4. Expect: wheels stop within 100 ms; `[ROBOT] stopped: IMU unsafe or stale` and `[ROBOT] IMU stop data: ...` once; then `Buddy4: IMU read failed` / `init failed` at most once per second with a failure count.
5. Send PAUSE, then RESUME from the dashboard: each must produce a `[ROBOT]` line (paused, or refused while stopped). Nothing ignored. The robot must stay stopped until reboot.
6. Put SDA back: `Buddy4: LSM303DLHC initialized` returns; the robot must still stay stopped (latched).
7. Repeat 10 times; also once by pulling SCL instead of SDA. If a `Buddy4: FATAL core N cannot block ...` line ever appears, keep the whole log and record its `sysstat`/`primask` values: they show which kernel state leaked (the kernel fix is still open).
